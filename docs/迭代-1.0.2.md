## 1. 背景与瓶颈（R01）

当前筛选先完成全部关键词候选收集（`collectCandidates`），再逐个确认库存与状态（`verify`）。库存缓存（默认 **1 小时**）和详情缓存（30 秒）已在确认阶段使用，能减少重复请求，但不能提前返回本地命中。

| 瓶颈 | 现状（离线诊断） |
|---|---|
| 首条结果前置等待 | 400 个满足条件的账号冷启动：先完成 20 次搜索才开始第一次库存请求；首次非空结果出现在 VERIFYING 阶段 |
| 重复搜索 | 同条件立即重查，库存与详情请求为 0，但仍重新搜索 20 次，候选阶段无结果显示 |
| 必要的库存/详情请求 | 冷启动库存 400、详情 400；默认 30 次/分钟时每次请求间隔至少 2 秒 |
| 关键词缺陷 | 平台搜索不是“名称包含”匹配；「格洛克」「加利尔」在真实平台为 0。离线重放：真实满足 1 个，输出 0 且 `incomplete=false` |
| 状态过滤隐藏结果 | 默认“仅可租”过滤掉状态未知的结果；新增“状态确认中”数据不保证可见 |
| 停止/继续 | 候选阶段无停止按钮；候选阶段停止后继续会从第 1 页重取 |

优化分别针对：候选前置等待、重复搜索、必要的库存/详情请求。“候选数 × 2 秒”不代表所有场景的总耗时；匹配且状态未知的账号通常还需一次详情请求。

## 2. 范围

### A. 搜索与筛选（必须）

**A1 关键词证据（R02）**
- 每个子类的平台关键词保存三类相互独立的证据，各带验证日期、规则版本、样本范围和引用文件：
  - `queryable`：可查询。搜索成功或 total>0 只能证明这一项。
  - `precision`：精确性。搜索命中的账号完整库存确实含该子类，用完整库存抽样交叉核验；结论只代表样本精度。
  - `coverage`：覆盖。结合已知库存样本、别名和更宽的关键词交叉检查，确认没有明显漏召回。
- 证据不足时标“未验证”，走 A2 回退。只有 `precision` 与 `coverage` 都达到快速路径要求的映射，才允许跳过库存确认（A3）。
- 先认证默认内置方案用到的类别（蝴蝶刀、爪子刀、锯齿爪刀、M9 刺刀、手套/裹手、AK-47、M4A1、USP、格洛克18型）。其余类别未认证时不阻塞应用，只是不走快速路径。
- 约 45 次只读搜索作为初始探测预算；精确性与覆盖认证另需库存抽样请求，按类别分批进行，不承诺一轮完成。
- 不把“含空格必为 0”“未登记前缀必为 0”当作平台通用规则。接口规范 R8 的旧“子串”假设由本条替换。

**A2 零结果回退（R03）**
- 可疑的零结果（关键词未认证、证据过期，或与本地已知库存矛盾）：
  1. 先用已知别名或其他可靠的必要条件作为候选入口；
  2. 没有其他可靠入口时，用当前租期的空关键词列表发现候选，再做完整库存确认；
  3. 所有候选来源都失败时显示“未完成：候选来源不可用”，不显示完整的零结果。
- 历史缓存为空、接口失败、关键词证据过期，都不能作为“无匹配”的证据。
- 已认证关键词返回 0，只说明当次查询在其明确范围内为 0；本地收藏和历史已知账号仍按既有产品范围参与匹配。

**A3 搜索证据快速路径（R04）**
- 每个结果记录匹配证据，分两种：有效的完整库存，或已认证的类别搜索证据。只有全部有效条件行都有充分证据时才认定组合匹配。
- 适用快速路径的行：只有类别、没有皮肤，且所有类别的映射都已认证。同一行有类别和皮肤（同件约束）或只有“宽”关键词时，仍需完整库存确认。
- 未读库存的结果，`hitCount/score` 为“未计算”，不用条件行数、展示位数或 0 代替。卡片显示“类别条件匹配，库存详情按需加载”；按匹配度排序只比较已确认库存的结果，默认改为价格排序。
- 打开详情或补读库存后若发现不符：撤销该账号的匹配，该关键词降级为未认证。
- “扫描匹配阶段可以零库存请求”只限扫描任务本身；打开详情、收藏宫格补图、契约抽查、回退路径读库存合法，按任务来源分别统计。
- 请求数（固定夹具、无重试）= 搜索请求数 + 需核验动态字段的账号数 + 回退所需的库存请求数；命中缓存的请求扣除，失败重试另计。真实平台只报告观察值，不以最终结果数作上界。

**A4 大类展开与求交（R06）**
- 大类展开（任意手套 =「手套」∪「裹手」，任意刀 = 各刀型并集）作为查询规划器的候选策略之一。映射必须覆盖当前词典的全部类别，无法证明覆盖时保留宽入口加库存确认。
- 查询规划分别估算两条路径的成本，选更省的：
  - 快速路径：收集足够的搜索证据；
  - 库存路径：用一个覆盖目标的必要条件取候选，再一次检查所有行。
- 只有额外搜索预计能省下更多库存/详情请求时才做求交。未完成、失败或被截断的分页集合，不能用来硬性排除其他可靠来源的候选。

**A5 流式输出（R05）**
- 每取得一页搜索结果，就按账号更新已满足的条件行。账号一旦有足够证据满足全部行，立即输出，不等其他页。
- 需要库存确认的路径，读到候选页就开始检查。
- 首条结果立即推送，之后按 100–300 ms 合并推送。
- 同一账号从多个来源出现时按账号去重合并。只有拿到充分的正向证据才显示为组合匹配；“在尚未读完的页里没看到”不等于不匹配。
- 默认“仅可租”视图下，待确认结果进入独立的“已匹配，状态待确认”区域，必须可见；“当前可租”数量只统计已确认可租的结果。已命中但为租赁中/已下架的账号，界面说明隐藏了多少个，不能一直只显示骨架屏。

**A6 五分钟搜索缓存（R07）**
- 缓存键（查询范围）：用户范围、平台原始关键词、租期、用券筛选、分页大小、排序和已生效的服务端筛选参数。页号是该范围内的分页键。若以后把价格下推到平台，价格也必须进入键。
- 每个查询范围另外记录：查询代际、各页获取时间、已读取页、total、是否完整、失败原因、关键词规则版本。
- 五分钟内复用有效页，缺的页继续取；过期、用户点“刷新最新”或规则升级时失效。不同代际的页不拼成一个完整快照。
- 只有部分页的结果不能写成“完整的空结果”；完整查询结果与分页片段分开存。
- 使用缓存候选时显示“候选快照时间”，并提供“刷新最新”入口。五分钟内可能漏掉窗口内新上架的账号；状态与价格刷新照常进行，但不会让缓存候选变成实时全量。

**A7 任务完整性与恢复（R14，新增）**
- 扫描任务保存：每个来源的页游标、去重后的账号、各条件证据、待确认队列、结果和失败页。
- 候选阶段与确认阶段都能停止；继续时复用已成功的页和已有结果，不从第 1 页重取。
- 新扫描使用新的 scanId/代际，旧请求和退避重试不得更新新任务。
- 分别显示：发现是否完成、已检查数量、待检查数量、覆盖是否完整。发现未结束时不显示固定总量的百分比。
- 以下情况保留具体的 `partial` 原因，不显示“完整完成”：缺页、重复页、达到 200 页上限被截断、无法确认的 total 变化、失败账号未重试、提前遇到空页。失败页提供恢复入口，不只有失败账号重试。
- “已扫描完成”和“覆盖完整”是两件事。覆盖完整要求所选来源覆盖结束、待确认项已处理、没有未解决的缺页或错误。长时间暂停后，页码分页可能因上下架而移动，继续时重新核对并去重，不承诺平台一致快照。

**A8 测试夹具（R02）**
- 保留可控的合成平台，用于大规模算法测试。
- 增加有来源的关键词响应回放夹具，覆盖已观察到的拼写差异（空格、前缀、全称）、宽匹配、零结果和缺页。未知字符串不自动视为已验证规则。

### B. 本地缓存优先（必须）

**B1 上次结果，按账号增量合并（R08）**
- 先加载本次用户范围内的历史结果，在本次扫描发起远程搜索前推送首份本地结果；不阻塞独立的订单或监测请求。历史条目标明匹配证据和更新时间。
- 新数据按 accountNo 增量合并：
  - 证实符合：更新；
  - 证实不符：立即退出当前匹配集；
  - 请求失败：只标“未能复核”。
- 对“本轮没再出现”的账号，只有对应覆盖已完成、且来源范围允许排除时才移除；失败或局部扫描不据此删除。
- 区分“最近一次完整快照”和“当前部分进展”。停止或异常结束的快照可以保存，但必须带 `partial`。本地收藏和历史账号不因不在本轮货架查询中出现而被删除。

**B2 本地匹配入口与离线（R09）**（文案统一为“本地匹配”）
- 本地匹配与远程扫描分别启动：
  - 本地路径只读有效缓存，以及明确用户范围内的历史结果，不依赖先完成在线认证；
  - 远程路径仍遵守现有登录态要求。
- 账号快照与库存各自保留验证时间（`knownAccounts()` 不再丢弃快照时间）。无网络、身份未确认或库存过期时，只显示历史/待核验状态，不计为实时可租。新安装无缓存时显示“无本地记录”。
- 两种离线情况分别处理：
  - 同次运行中从在线变为断网；
  - 重启后始终离线：恢复最近一次可识别的用户范围（`lastProfileId`），不合并多个用户的收藏、方案和结果。
- 共享的库存缓存与用户相关的结果使用不同的存储作用域。
- 本地匹配分批读取：先返回已知历史命中，再补算其他账号，避免为遍历全部本地库存制造新的首屏等待。过期、损坏或 schema 不兼容的记录不作为当前匹配证据。

**B3 小条件变化（R10）**

| 改动 | 行为 |
|---|---|
| 收紧价格或勾选仅可用券 | 在已有**完整快照**中立即计算子集并标注快照时间；核验价格、租期支持、用券标记与状态。旧查询只部分完成、快照已过期或用户要求最新范围时继续发现，不宣称旧子集等于当前平台全集 |
| 放宽价格或取消仅可用券 | 先显示可复用的本地结果，再补取旧范围没覆盖的候选；搜索页本来没按价格过滤时，优先复用已缓存页重新筛选 |
| 更换租期 | 库存匹配结论可复用；重新确认该租期是否支持、价格是否有效，并按新租期发现候选。快照里有六种价格字段，不等于每种都有值、有效或已开放 |
| 修改饰品条件 | 复用有效的原始库存重新匹配；只有条件指纹相同才直接复用旧的行命中结论 |

“只改价格不触发库存请求”限定为对应库存证据仍有效；库存过期、丢失或算法版本变化时允许刷新。

**B4 两层缓存与在途合并（R11）**
- 库存匹配层：键为账号库存版本/内容标识 + 规范化饰品条件指纹 + 匹配算法/分类词典版本；保存命中结果、命中去重键和验证时间。不含价格、租期、用券。条件行顺序调整不影响指纹；重复行不重复计数；同件约束保留。
- 查询结果层：键包含全部业务条件（饰品条件指纹 + 租期 + 价格 + 用券）。
- 搜索证据路径保存自己的证据类型，不与完整库存结论混用。
- 按账号和接口合并在途请求：扫描和详情同时读同一账号库存时只发一次。强制刷新、优先级提升与单个消费者取消规则要明确，扫描停止不能取消用户详情需要的读取。

**B5 库存缓存默认值迁移（R12）**
- 新装默认库存缓存 6 小时。
- 升级时保留已有的有效值，包括 1 小时、6 小时、1 天和本次运行；不以“值等于旧默认”判定用户没有选过。
- 旧设置里缺少该字段，或值非法时，保留旧的 1 小时行为。
- 设置 schema 增加迁移版本号，用来区分新装和升级。
- 库存缓存时效与账号状态、价格时效相互独立；调高默认值只扩大复用窗口，不作为算法提速的证据。

### C. 收藏监测卡片 3×3 宫格（应当，R13）

| 编号 | 内容 | 验收 |
|---|---|---|
| C1 | 一行一个收藏，卡片内用 3×3 宫格代替单张缩略图；每格一张缩略图，悬停显示名称、磨损、估价 | 1200×760、1440×900 下不溢出、无大片留白 |
| C2 | **选图**：按库存唯一键去重；刀、手套、主战武器各取估价最高的至多 2 件；再从未选中的饰品里按估价补满 9 件；估价缺失的排在后面，同价按唯一键稳定排序；不足 9 件留空格 | 单元测试：各类不足 2 件、总数不足 9 件、估价缺失、同价排序 |
| C3 | **摘要数据**：收藏摘要与 DTO 增加带版本的多图条目和来源时间，兼容旧的单缩略图摘要。区分“完整库存为空”与“尚未读取库存”，确认库存为空后不再回退到旧展示位 | 旧摘要升级后可读；空库存不复活旧图 |
| C4 | **不被覆盖**：由完整库存生成的宫格，不会在下一轮普通收藏同步时被只有展示位的摘要覆盖（`summarize()` 与 `summary_json` 的整体更新路径一起改） | 下一轮同步不降级宫格 |
| C5 | **后台补读**：没有完整库存时先显示展示位（最多 5 件），后台补读一次完整库存。补读任务按账号去重，滚动或重绘不重复创建；缓存有效时不重读；失败记录状态、按受控条件重试。新增“后台”优先级，低于交互、监测和扫描，共享总预算；支付进行中、退出、身份切换时暂停或取消（接入现有支付暂停逻辑，不能只阻塞扫描优先级） | 重复打开只补一次；支付期间不补读 |

## 4. 实施顺序

1. **方案与数据契约**：本文定稿；明确哪些条件允许搜索证据直接判定，哪些继续读完整库存；同步修订接口规范（替换 R8）、状态机（完成定义、证据类型、匹配度含义、缓存时效）、产品文档（状态待确认区域、刷新最新、默认排序）。
2. **最小回归夹具**：把审阅归档的“错误零结果”“候选阶段停止继续”改成修复后的预期；新增“后续页挂住，首条仍须可见”的服务测试，以及默认筛选下的界面测试。
3. **共享能力**：扫描任务上下文、逐页输出、本地先返回、时间与证据字段、增量合并、缓存键、在途合并。
4. **快速路径与缓存迁移**：先认证并覆盖默认内置方案的类别，其他类别保留回退；完成五分钟分页缓存与 TTL 迁移。
5. **收藏宫格**：复用库存缓存和在途合并，接入后台优先级与暂停机制。
6. **验收与回填**：按 §6 记录请求数、首条与全量时间、关键词契约版本、未完成范围；更新版本说明与验收记录；打 1.0.2 安装包。

- **主战武器**：步枪 + 狙击步枪（AK-47、M4A1、M4A4、AWP 等）；手枪、冲锋枪不算。

## 6. 验证计划（R15）

| 指标/场景 | 验收要求 |
|---|---|
| 首个历史命中 | 有效本地证据就绪后先推送本地结果；有限规模夹具目标 1 秒内，不含远程状态确认 |
| 首个本轮组合匹配 | 后续页阻塞时，已有充分证据的账号仍先显示 |
| 首个可租结果 | 单独统计状态确认后真正可租的时间，不拿待确认卡片代替 |
| 推送到可见 | 首条结果立即推送；离线界面目标 300 ms 内可见；单元测试与浏览器端到端测试分别覆盖 |
| 全量扫描 | 分别记录搜索、库存、详情、失败重试、后台补图请求数，冷缓存与热缓存分开报告 |
| 正确性 | 固定完整数据集上，与完整库存穷举的结果集合一致；缺页、旧快照不能作为全量结果 |
| 线上契约 | 每个关键词保存观测范围与证据；不把有限抽样称为全站完整召回 |
| 关键回归 | 零结果回退、同件约束、OR 分支、状态过滤可见性、离线入口、TTL 迁移、停止继续、身份切换、支付暂停 |

各条目的专项用例：
- R03：单一未知类别、全部关键词可疑、可信来源失败、平台为 0 但本地有命中。
- R07：第一页命中但第二页缺失、缓存中某页失败、不同排序、关键词映射变化、五分钟边界、强制刷新、切换用户。
- R08：旧账号被证实缺饰品后立即撤出；后续页断网时，未复核的历史账号仍可查看并标注；刷新期间不清空、不重复。
- R09：在线后断网、离线重启、身份切换、无缓存、缓存过期。
- R10：旧结果部分完成、原先超预算的账号降价、用券标记变化、租期停用、缓存过期。
- R11：调换条件行、增删一行、更换库存版本、词典升级、重复行、清缓存、两个消费者同时请求且其中一个取消。
- R12：新装、已有显式 1H、SESSION、6H/1D、旧设置缺字段、配置非法。
- R13：选图规则、同步不降级、空库存不复活旧图、重复打开只补一次、支付期间不补读、旧摘要升级。
- R14：两个阶段都能停止；短暂停止后继续不重取成功页；旧请求迟到不污染新查询；失败页、提前空页、200 页截断都不显示完整完成。

速度预期：默认 30 次/分钟时，请求之间至少相隔 2 秒；“搜索 + 库存 + 详情”三次请求理想情况下也需约 4 秒加最后一次响应。不承诺冷启动几秒内必出结果；目标是不再等待不必要的全量分页，真实平台记录 p50/p95，缓存与快速路径的收益分开报告。

另保留：类型检查、静态检查、全部单元测试、离线预览界面验收（上次结果提示、本地匹配、状态待确认区域、刷新最新、收藏宫格）、1.0.2 安装包与版本说明。
