# 开发任务与验收

> v1.0 · 2026-11-07 · 工作范围、依赖、交付和验收规则

本轮交付的是开发基线与能力验证，正式业务应用从 M1 开始实现。M0 已完成；M1–M6 为执行顺序固定的开发工作包，不含选型探索任务。第一期包含 G、P1–P7、需求中的全部“必须”和“应当”条目；F1.8 精细筛选、F3.6 续租不进入第一期。

## 3. 开发流程

1. 每个工作包从当前主分支建立 `codex/<任务编号>-<描述>` 分支；提交范围包含对应实现、必要测试与文档变更。
2. 先实现共享类型、平台适配和领域状态，再接页面；界面只渲染主进程 DTO，不复制计费、状态判定或调度规则。
3. 使用虚拟账号和脱敏契约样例开发。默认测试不读取真实客户端、不写平台收藏、不创建订单。
4. 核心状态变更使用事务并附本地追踪 ID；日志只包含脱敏字段。检查新增依赖版本和许可，更新锁文件。
5. 开发者运行对应工作包用例及统一检查；评审重点为需求映射、错误恢复、用户数据保留、请求预算和凭证边界。
6. 每个工作包完成时更新任务完成记录；合并后只基于通过检查的主分支制作下一工作包的集成基础。
7. 规范变更提升文档小版本，记录原因、受影响任务和回归范围，不在代码中保留与文档相冲突的第二套流程。

代码采用 UTF-8、LF、2 空格、单引号和分号；Biome 执行格式化及推荐规则。TypeScript 开启 `strict`、`noUncheckedIndexedAccess`、`noUnusedLocals` 和 `noUnusedParameters`。平台响应先按 schema 解析，禁止以 `any` 穿透领域层。

## 4. 检查命令与持续集成

M1 创建以下根目录脚本；含义在整个第一期固定。

| 命令 | 执行内容 |
|---|---|
| `npm ci` | 按锁文件安装 |
| `npm run typecheck` | 主进程、preload、renderer、共享契约分别运行 `tsc --noEmit` |
| `npm run lint` | `biome check` 检查源码及测试 |
| `npm test` | `vitest run`；领域、契约、调度和数据库集成样例 |
| `npm run test:auth` | Python unittest，运行人工生成的 LevelDB 样例；无真实用户目录 |
| `npm run build:auth` | 用固定 Python 依赖和 PyInstaller 冻结解析器 |
| `npm run build` | `electron-vite build` |
| `npm run package:win` | 检查解析器构建产物后执行 NSIS x64 打包，不上传发布 |

GitHub Actions 使用 Windows x64 runner、Node 24.14.0、Python 3.11.9。PR 执行依赖安装、类型、静态检查、离线测试与构建；版本标签额外打包并保存安装包、SHA-256 和许可清单为构建产物。CI 不持有 5E 登录态，不调用平台鉴权接口，不自动创建交易。

交互验收在本机通过 `ego-browser` 执行前端页面检查，并结合已安装应用验证托盘、通知协议和进程生命周期。CI 的离线测试、浏览器交互验收、真实平台抽样是三种独立证据，不相互替代。

## 5. 第一期验收矩阵

| 范围 | 固定场景 |
|---|---|
| 登录与身份 | 无目录、无记录、删除/空值、过期、业务 401、重读成功、用户切换、正在写入的客户端存储 |
| 数据与安装 | 首装、升级、迁移失败恢复、中文路径、无 Python、默认卸载保留业务数据、主动清理选项 |
| 筛选 | 空条件、单条件、同件约束、多条件、交集为空、分页去重、缺页、缓存过期、停止继续、切换条件后的迟到响应 |
| 收藏与监测 | 只增不删、移除恢复、写回失败、快速正反操作、首次基线、错误恢复、可租新周期、睡眠/重启、多账号合并 |
| 通知与安全 | 通知被系统抑制、冷/热协议唤起、无效和重放 nonce、跨用户动作、未知 IPC、外部跳转与恶意文本 |
| 价格与出码 | 六种租期、包时段边界/星期、元分转换、券规则、券缺页、渠道失效、价格变化、重复点击、预检取消 |
| 订单恢复 | 创建前/响应后各持久化边界强制终止、创建响应丢失、付款码加载失败、已付/取消竞争、释放失败、归零后断网、人工核对 |
| 视觉与操作 | 两种窗口尺寸、Windows 100%/150% 缩放、键盘导航、Esc、空态/失败、图片破损、长列表虚拟滚动 |

金额、创建次数、凭证边界、数据保留、支付/释放状态和请求上限是阻断发布的验收项。正常线上抽样只验证当前版本适配；不以反复创建未支付订单、制造封禁或主动耗券作为常规回归。

## 6. 发布流程

1. 完成 M1–M6 验收记录，更新版本与版本说明；确认第一期范围和已知产品限制均与文档一致。
2. 从版本标签干净构建，生成安装包与 SHA-256；核对第三方 MIT 等许可和分发依赖清单，不打包平台前端源码。
3. 在 Windows 10 22H2 x64、Windows 11 x64 的干净用户环境完成首装/升级/卸载矩阵，并保留脱敏验收记录。该矩阵是正式产品发布门槛，不是本轮能力样例的已完成声明。
4. README 提供客户端前提、首次启动、手动出码、返回客户端上号、请求设置、故障恢复、风险声明和卸载数据规则；公开截图使用虚拟数据。
5. 发布仓库转公开、版本标签和 Release 属于发行操作，在发行工作包完成后执行；本轮文档定稿不提前发布。发布不启用后台更新或遥测。
