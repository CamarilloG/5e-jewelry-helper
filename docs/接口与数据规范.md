# 接口与数据规范

> v1.0 · 2026-11-07 · 平台适配器实现契约
> 依据本轮官方接口调用及公开前端包；证据和验证方式见 [验证记录](验证记录.md)。

## 1. 通信规则

- 基址：`https://gate.5eplay.com/rentinterface/http/v1`。下表路径均追加在此基址后，方法均为 POST，正文 JSON。
- 请求头仅添加 `Content-Type: application/json` 和客户端现有 `Authorization`，保持读取到的凭证格式，不擅自添加或移除 Bearer 前缀。
- 仅主进程发送鉴权请求；重定向不得把 Authorization 带到其他源。TLS 校验保持开启。
- 成功包按 `status === true` 判断；同时校验该接口需要的 `data` 字段。不能用 HTTP 200 或顶层 `success` 单独判定业务成功。
- HTTP 401 或业务 `code=401` 统一映射 `AUTH_EXPIRED`。其余错误按代码、字段和当前阶段映射；关键数据不符合 schema 时进入 `CONTRACT_CHANGED`。
- 读取请求超时 15 秒；创建订单 20 秒且不自动重发；解锁 10 秒且不自动重复发送。全部纳入同一限速队列。
- 搜索与收藏分页固定 `size=100`，订单记录分页固定 `pageSize=10`，均采用本轮成功调用的大小，不探测更大上限。

分页停止条件为已收齐响应总数或返回空页。按账号号去重；重复页、页内结构错误、任何页失败都会把本轮标为不完整，禁止据此删除或判定平台取消收藏。搜索和收藏的 `total` 统一解析为非负整数。

## 3. 账号与库存

| 字段 | 规则 |
|---|---|
| `accountNo` | 全流程使用字符串；界面编号、API 参数与本地键一致 |
| `shelfStatus` | 整数 1 为在架，其他整数按平台前端规则显示下架；缺失或类型不合法为未知 |
| `rentStatus` | 0 为可租、1 为租赁中；陌生枚举为未知，不推断可租 |
| 状态优先级 | 缺少关键字段 → 未知；不在架 → 已下架；在架且租用 → 租赁中；在架且空闲 → 可租 |
| `expireTime` | Unix 秒字符串；仅作预计可租时间，不能到点就本地改为可租 |
| `rentPeriod` | 小时租起租小时数，不是状态枚举；结合 `hourDuration` 校验数量 |
| `isFavorited` | 平台收藏状态；独立于本地收藏/移除记录 |
| `value,availableValue` | 元的十进制字符串；估值展示，不参与订单实付计算 |
| `displayInventory` | 列表展示位，不能替代完整库存 |
| `marketName,marketHashName` | 展示与名称归一化输入，不把卖点标签当作库存证据 |
| `firstType` | 大类，如“匕首”“手套”；刀型等细类由饰品名称的武器前缀解析 |
| `assetid` | 字符串；与账号组合用于同一库存内去重，不转 JS Number |
| `wear,price` | 原始十进制文本；缺失显示“—”，不补零 |
| `ossImgUrl,steamImgUrl` | 优先官方 OSS 图，失败再用返回的备用图；失败显示占位，不中断筛选 |
| StatTrak 展示 | 优先识别规范市场名称中的 `StatTrak`；不能将 `hasStattrak=-1` 当作唯一否定依据，本轮存在名称与该字段不一致的样例 |

分类词典和常见皮肤名称建议随包发布并版本化，不依赖额外热词接口。大类采用精确归一化比较；细类从武器前缀匹配，忽略空格、全半角和装饰符号。名称按归一化后的中文包含关系匹配，不拼接多个词发送给平台搜索。未知分类保留原始名称并允许名称筛选，不猜测归类。

P1 的平台搜索与本地已知账号组成“本次搜索范围”。“全部/租赁中/已下架”只过滤这个范围，不宣称枚举平台全部下架账号。收藏保留的账号通过 `get_info` 单独查询。

## 4. 租期与数量

| 文案 | 内部枚举 | 搜索/下单编号 | 价格字段 | 数量规则 |
|---|---|---:|---|---|
| 小时租 | `HOUR` | 1 | `hourPrice` | `hourDuration` 中的正整数，且不少于 `rentPeriod` |
| 天租 | `DAY` | 2 | `dayPrice` | `dayDuration` 中的正整数 |
| 周租 | `WEEK` | 3 | `weekPrice` | `weekDuration` 中的正整数 |
| 包早 | `EARLY` | 4 | `morningPrice` | 固定 1 次 |
| 包午 | `NOON` | 5 | `noonPrice` | 固定 1 次 |
| 包夜 | `NIGHT` | 6 | `eveningPrice` | 固定 1 次 |

账号支持一档租期的条件是账号 `rentType` 包含其编号且原价大于零。零价代表该档未开放；券后零元是另一种情形。不能因为 `weekPrice` 有值就绕过账号未开放周租的限制。

包时段规则固定在版本化的平台适配配置中，按北京时间（`Asia/Shanghai`）计算：

| 租期 | 可下单窗口，左闭右开 | 使用时段 | 星期限制 |
|---|---|---|---|
| 包早 | 07:00–09:00 | 当天 07:00–12:00，实际从下单成功起 | `weekRangeMorning` |
| 包午 | 09:00–10:30 | 当天 09:00–14:00，实际从下单成功起 | `weekRangeNoon` |
| 包夜 | 00:00–02:00 | 当天 00:00–07:00，实际从下单成功起 | `weekRangeEvening` |

星期值 1–7 对应周一至周日。三个窗口来自本轮前端规则，不声称详情 API 返回了起止时间；价格与可用星期从账号接口读取。截止边界以平台最终校验为准，拒绝时停止出码并展示原因，不尝试改参数绕过。

库存和方案等普通记录按操作系统时区展示；涉及包早/午/夜的时间明确标注“北京时间”。服务器 `timestamp`、订单截止时间、账号到期时间先从秒转换为内部 UTC 毫秒。付款倒计时使用服务器截止时间和单调时钟推进，休眠恢复立即重新查支付状态。

## 5. 价格、券与支付渠道

### 金额

- 账号单价、库存估值、租赁订单 `totalRealAmount` 和订单详情 `realAmount` 的单位为元。
- **创建订单请求中的 `realAmount` 单位为分，发送十进制字符串。** 不能复用订单详情的同名字段直接传回。
- 计算原始租金：`Decimal(当前单价元) × 数量`，先按 `ROUND_HALF_UP` 保留两位小数，再乘 100。全程禁止用二进制浮点数直接计费。
- 第一期开价使用账号详情的原价。列表展示首单价和活动价，但不把营销标签自动转换为下单报价。平台返回金额不一致时停止本次创建、刷新详情，让用户再次手动发起；不静默涨价后重发。
- 券后金额按以下公式计算，保留 Decimal 结果并以字符串传送；显示为 `金额分 / 100`，向下保留两位小数，与当前平台前端一致。

### 优惠券

只有 `platformCouponConfig !== 0`、`useCoupon !== 0`，且状态、租期、有效期和门槛都通过的券才能参与选择。

| `couponType` | 适用范围 |
|---|---|
| 1 | 全部六种租期 |
| 2 | 三种时段租 |
| 3 / 4 / 5 | 包早 / 包午 / 包夜 |
| 6 | 小时 / 天 / 周 |
| 7 / 8 / 9 | 小时 / 天 / 周 |
| 其他值 | 不自动选择，按无可用券处理；保留正常原价出码能力 |

| `discountType` | 计算与额外限制 |
|---|---|
| 1 | 原始金额分 × `discountValue` |
| 2 | 原始金额分 − `discountValue × 100`；优惠额不得超过原价元 |
| 3 | 原始金额分 − `discountValue × 100`；原价元须达到 `thresholdAmount` |
| 4 | 0 元 |
| 其他值 | 不自动使用 |

结果下限为 0。选实付最低的券；相同优惠额时依次选择门槛较高、到期较早、ID 字典序较小的券，保证结果可复现。无可用券或用户关闭自动用券时传 `propId:0`。本轮账号没有可用券，券计算和异常类型以公开调用逻辑及人工样例测试为依据。

沿用当前客户端的券列表请求格式；`nextPageToken` 非空或 `totalSize` 大于已取得条数时，视为列表不完整，暂停自动用券出码并提示用户关闭自动用券后重试。不猜测游标字段或在缺页时声称选出了全局最优惠券。

### 渠道和付款码

`payChannel=1` 为支付宝，2 为微信；`payChannelId` 必须来自当前 `pay/channel/list`。没有返回的渠道在界面禁用。既有预设的渠道失效时打开参数编辑，不能静默替换用户的支付方式。本轮返回支付宝 `payChannelId=4`，此值只作验证证据，不能写死到业务代码。

`codeUrl` 是平台提供的付款码图片地址或图像数据，不是待二次编码的二维码文本。受控加载到内存展示，完成/关闭后释放；加载失败仍需保留订单状态与释放入口，不能重新创建订单来刷新图片。

## 6. 三种订单标识

| 标识 | 来源 | 用途 |
|---|---|---|
| `paymentOrderId` | 创建响应 `orderId` | 唯一用于 `get_status` |
| `rentalOrderNo` | 订单列表 `orderNo` | 用于 `order/details` |
| `rentalChildNo` | 订单详情 `orderChildNo` | 付款记录展示与关联，不作为 `get_status` 参数 |

真实测试中支付订单 ID 与另外两个字段不同，本笔租赁订单号和子订单号相同。字段按用途区分，不假定三个值必然不同，也不因偶然相同而混用。用户点击创建前先持久化本地 `attempt_id`；响应到达后立即保存 `paymentOrderId` 和服务器截止时间，再展示付款码。

创建响应丢失时不能从租赁订单号反推支付订单 ID。进入“创建结果确认中”，暂停新的出码；执行受控释放及官方客户端订单核对流程，见状态机文档。

## 7. 支付与错误映射

| 条件 | 程序行为 |
|---|---|
| `payStatus=1` 且 `abnormalReason=0/空` | 支付成功，停止轮询，禁止解锁，提示回客户端上号 |
| `payStatus=0,abnormalReason=0` | 待支付 |
| `payStatus=0,abnormalReason=5` | 平台确认超时，停止显示可支付二维码并申请释放 |
| `abnormalReason=1` | 用户封禁，停止出码 |
| `abnormalReason=2` | 账号已被他人租用，停止出码 |
| `abnormalReason=3/6` | 账号已下架 |
| `abnormalReason=4` | 支付异常，提示去客户端核对，不声称已退款 |
| `abnormalReason=7` | 不在付款时段 |
| `abnormalReason=8` | 数量/时长超出范围 |
| 创建响应 `code=533` | 终止本次出码，展示平台原始业务提示；不自动重试，不擅自命名为某一种冻结原因 |
| `code=400` 等明确业务拒绝 | 展示脱敏原因，修正输入或重新读取后由用户重新发起 |
| 陌生支付状态/异常码 | “订单状态需在客户端核对”，保持恢复记录，阻止自动创建 |

`unlock_account` 的 `status=true` 仅记为“释放请求已受理”。它不等于“订单已取消”，也不能作为支付终态。服务端结果、客户端倒计时归零和本地弹窗关闭必须分开记录。
