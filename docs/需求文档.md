# 饰品驿站助手 —— 需求文档

> 项目名称：**饰品驿站助手**，英文代号 / 仓库名 `5e-jewelry-helper`。
> 本文件管理产品范围、约束与验收目标。实现基线见 [技术选型](技术选型.md)、[接口与数据规范](接口与数据规范.md) 和 [业务流程与状态机](业务流程与状态机.md)。
> 版本：v1.0 定稿 · 2026-11-07

---

## 1. 背景

5E 对战平台客户端内「饰品驿站」是一个 Steam 账号租赁功能：用户按小时/天/周或包早/包午/包夜时段，租用库存里带高价 CS2 饰品的账号来游戏。其内置的筛选与监测能力较弱：

- 搜索只支持**单个中文关键词**，无法做「某把刀 + 某种图案」「同时含 A 饰品和 B 饰品」这类组合筛选，也无法按价格/租期叠加保存条件。
- 列表每个账号只展示 5 件饰品，想按完整库存找特定饰品很费力。
- 收藏的账号是否「当前可租」要靠人工反复刷新。
- 想租的热门账号一空闲就会被别人抢走，用户很难蹲到。

本工具是一个**第三方桌面小工具**，在不改动客户端、不替用户做支付的前提下，提供比原生更好用的筛选、收藏监测和半自动出码。

## 2. 目标

- 让用户能用**精确的饰品条件**（名称、分类、组合）快速找到符合要求的可租账号。
- 让用户能**被动等待**而不是主动盯着：收藏的账号一空闲就主动提醒。
- 把「发现空闲 → 发起下单 → 拿到付款码」这条链路压到**用户点一下**即可，但支付与上号仍由用户本人完成。
- 工具面向**开源分发**，任何安装了 5E 客户端的用户都能直接用，不依赖作者的任何服务器或账号。

## 3. 用户与使用场景

- **主要用户**：在 5E 平台租号打 CS2 的玩家，有特定饰品偏好（例如只想租带某把刀的账号），且会蹲热门账号。
- **运行前提**：用户本机已安装 5E 客户端并已登录过。
- **典型场景**：
  1. 用户设定筛选条件「库存里有蝴蝶刀多普勒、且时租 ≤ 10 元」，一次性看到全部符合的可租账号及其库存图。
  2. 用户把几个心仪账号加入收藏；人离开电脑去忙别的；某账号空闲时，桌面弹通知。
  3. 用户点通知里的「一键出码」，工具按该收藏的预设发起下单，弹出付款码；用户扫码付款，再回客户端上号。

## 4. 功能需求

### F1 便捷的饰品筛选

| 编号 | 需求 | 优先级 |
|---|---|---|
| F1.1 | 支持按**饰品大类**筛选（如爪子刀、蝴蝶刀、M9 刺刀、手套、匕首、步枪等），列出库存含该类饰品的可租账号 | 必须 |
| F1.2 | 支持按**饰品名称/皮肤**筛选（如多普勒、潘多拉之盒、渐变大理石等） | 必须 |
| F1.3 | 支持**多条件组合**：同一账号需同时满足多个饰品条件（交集），这是相对原生的核心增强 | 必须 |
| F1.4 | 支持叠加**价格区间、租期类型（小时租/天租/周租/包早/包午/包夜）** 等基础条件 | 必须 |
| F1.5 | 筛选结果需展示账号的**完整库存**（不止原生的 5 件展示位），含饰品名、外观/磨损、估价、缩略图 | 必须 |
| F1.6 | 支持把一组筛选条件**保存为常用方案**，下次一键套用 | 应当 |
| F1.7 | 可按价格、价值、匹配度排序；在本次平台候选与本地已知账号范围内区分当前可租/租赁中/已下架 | 应当 |
| F1.8 | 精细条件（图案模板 paintseed/paintindex、磨损值区间、是否 StatTrak、贴纸）作为高级筛选 | 第二期，排除第一期 |

> 说明：原生搜索匹配的是账号**完整库存**的中文饰品名，但只接受单关键词。因此 F1.3 的组合筛选由工具实现——用单关键词取候选，再在本地取交集并拉完整库存精确确认。

### F2 收藏与监测

| 编号 | 需求 | 优先级 |
|---|---|---|
| F2.1 | 用户可收藏/取消收藏任意账号；收藏列表持久保存在本地，并与 5E 平台收藏**双向同步**（只增不删合并；下单预设等只存本地）。写回平台仅在用户手动收藏/取消时发生 | 必须 |
| F2.2 | 工具定时检查收藏账号的**可租状态**（可租 / 租赁中 / 已下架 / 预计可租时间） | 必须 |
| F2.3 | 收藏账号由「不可租」变为「可租」时，**主动提醒**用户（Windows 桌面通知） | 必须 |
| F2.4 | 通知可点击，直接定位到该账号并可触发一键出码 | 必须 |
| F2.5 | 监测频率可配置，并有保守默认值，避免对平台造成过高请求压力 | 必须 |
| F2.6 | 可对单个收藏开/关监测；可查看每个收藏的当前状态与上次变化时间 | 应当 |

### F3 半自动出码（提醒 + 一键）

| 编号 | 需求 | 优先级 |
|---|---|---|
| F3.1 | 工具**不做自动锁单/自动抢单**；只在用户**手动点击**后才发起下单动作 | 必须（红线） |
| F3.2 | 用户点「一键出码」后，工具自动完成下单前的必要步骤（校验、发起订单），直接弹出**付款二维码** | 必须 |
| F3.3 | 每个收藏账号可**单独预设**下单参数：租期（小时租/天租/周租/包早/包午/包夜）、时长或次数、支付方式（平台当前返回的微信/支付宝渠道）、是否自动用券 | 必须 |
| F3.4 | 出码弹窗需展示：实付金额、所选租期、付款倒计时，并明确提示「未按时付款可能触发平台冻结」 | 必须 |
| F3.5 | 用户可在出码前取消；预检已发出、取消或平台确认超时后，工具应核对状态并申请**解锁/释放**；不将释放受理等同订单取消，结果不明时保留恢复记录并阻止重复出码 | 必须 |
| F3.6 | 为平台允许续租的既有订单提供续租出码 | 第二期，排除第一期 |
| F3.7 | 非收藏账号也可在账号详情中就地选择下单参数并一键出码（参数不保存） | 必须 |

> 关键前提：在本平台，「拿到付款码」本身就等于**创建订单并占住账号**，没有「只取码不占号」的途径。因此 F3 必须由用户手动触发，且工具要把「占单→未付→冻结」的风险明确告知用户。

### F4 支付与下单

| 编号 | 需求 | 优先级 |
|---|---|---|
| F4.1 | 工具帮用户走到「展示付款二维码」这一步；**实际支付由用户本人扫码完成** | 必须（红线） |
| F4.2 | 工具**不代为扣款、不托管用户支付凭证、不绕过扫码确认** | 必须（红线） |
| F4.3 | 支付后的**上号/下号一律回到 5E 客户端完成**（受反作弊限制，必须由客户端本地模块执行），工具不涉及 | 必须 |
| F4.4 | 出码后可展示订单支付状态（待支付/已支付/超时），供用户确认 | 应当 |

## 5. 非功能需求

| 编号 | 需求 |
|---|---|
| N1 | **本地运行**：不依赖作者或额外第三方后端；业务数据直连平台官方接口，工具本身不回传任何数据 |
| N2 | **凭证安全**：登录凭证只在本机读取，仅发送给指定的 5E 官方鉴权接口，**不发送至其他来源、不写入日志、不出现在界面**；相关代码开源可审计 |
| N3 | **请求友好**：对平台接口做限速与本地缓存，默认频率保守，避免被当作爬虫；全量库存扫描必须限速 |
| N4 | **桌面体验**：Windows 桌面程序，支持系统托盘常驻与原生通知；能展示饰品缩略图等图片内容 |
| N5 | **可分发/开源**：安装与使用门槛低，普通用户无需命令行；不打包任何平台密钥或作者私有信息 |
| N6 | **合规与免责**：调用的是平台私有接口，平台可能随时变更或封堵；README 需明确风险由用户自担，并声明工具仅做提醒+手动触发，不提供自动抢单 |
| N7 | **可维护**：接口与数据模型若变更，便于定位与更新 |

## 6. 约束与前提

- C1 **依赖客户端登录态**：工具读取本机 5E 客户端已有的登录凭证来调用接口；按凭证实际到期时间及接口鉴权结果判断有效性，不写死 30 天，客户端重新登录后工具重新读取。
- C2 **单会话限制**：5E 平台同一账号只允许一个会话在线，因此工具**不自行登录**（否则会把客户端挤下线），只复用客户端登录态。
- C3 **上号必须经客户端**：真正的 Steam 上号依赖客户端本地模块与反作弊校验，工具无法也不应替代。
- C4 **平台接口非公开**：无官方契约，接口随时可能变化。

## 7. 明确不做（Out of Scope）

- 自动支付、代扣款、托管支付凭证。
- 自动锁单、自动抢单、无人值守下单。
- 替用户在工具内登录 5E 账号。
- 工具内完成 Steam 上号/下号。
- 任何形式的服务器端组件、账号托管或数据回传。

## 8. 验收标准（MVP，第一期）

第一期范围：**F1 筛选 + F2 收藏监测 + F3 半自动出码（提醒版）**。达到以下即算合格：

1. 能读取本机客户端登录态并成功调用平台接口（失败时有清晰提示）。
2. 能用「饰品大类 + 名称 + 价格/租期」的组合条件筛选出可租账号，并展示其完整库存与图片。
3. 能收藏账号，并在收藏账号变为可租时弹出 Windows 桌面通知。
4. 能对每个收藏预设下单参数；点「一键出码」后弹出付款二维码，含金额、租期、倒计时与冻结风险提示；取消/超时执行状态核对与释放流程，异常可恢复且不重复创建。
5. 全程无自动支付、无自动锁单；上号引导用户回客户端。
6. 默认每分钟最多 30 次平台请求，所有功能共用预算；遇到限流按规范退避，不绕过平台限制。

## 9. 已定事项（原开放问题）

2026-11-07 全部定稿：

- 项目名称：饰品驿站助手（`5e-jewelry-helper`）。
- 技术栈：Electron + React + TypeScript + Ant Design + SQLite；完整版本与工程约束见 [技术选型](技术选型.md)。
- 代码仓库：开发期建 GitHub **私有**仓库，发布时转为公开（满足 N5 开源分发）。
- 精细筛选（图案/磨损/StatTrak/贴纸）：不纳入第一期，按 F1.8 留到第二期。
- 收藏监测频率：默认 1 分钟，下限 30 秒；请求速率默认上限 30 次/分钟（见产品文档 Q15、Q18、Q19）。
- 多人抢同一账号：工具不做自动抢；通知与「已被他人下单」提示中注明「先到先得，工具不代抢」（见产品文档 Q21）。

界面与交互层面的全部决策见 [产品文档.md §11](产品文档.md#11-决策记录)。

本轮证据和验证方式见 [验证记录](验证记录.md)，平台字段以 [接口与数据规范](接口与数据规范.md) 为准。相邻 [`5e-client-toolkit/文档/饰品驿站.md`](../../5e-client-toolkit/文档/饰品驿站.md) 保留为历史调查资料。要点：
